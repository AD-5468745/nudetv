| 순서 | 무엇 | 누가 | 무엇을 막나 |

| **①** | **텔레그램에서 해당 채널의 봇 관리자 설정 → '메시지 게시' 권한 끄기** | 대표님 단독 | **새 게시**를 즉시 막는다. 시스템 상태와 무관하게 확실하다 |

⚠️ **권한을 되돌리는 것만으로 재개하지 않는다.** 정지 구간에 밀린 것이 무엇인지 확인한 뒤 연다.

### `state/STOP`(시스템이 스스로 서는 층) — **아직 없다**

만들려면 아래 계약 5개를 **먼저 구현·검증**해야 한다. 그 전에는 "정지 수단"이라고 말하지 않는다
(시트가 바로 그 잘못을 저질렀다).

| 계약 | 조건 |
|---|---|
| 전달 | 정상·재시도·대장 변경 없는 틱에서도 원격을 확인하고 **모든 활성 실행**이 STOP을 적용한다. 반영은 "정상 동기화 조건에서 두 틱 이내"를 **시험 목표**로 하고, 실제 정지 여부는 확인 기록으로 판단한다(보장이 아니다) |
| 읽기 실패 | **정지 쪽으로 기운다.** 원격 갱신 실패도 판정 실패로 본다 — 오래된 사본에 STOP이 없다는 이유로 계속 발송하지 않는다 |
| 정지 중 큐 | 큐 생성과 클레임을 멈춘다. **이미 클레임했지만 전송 전인 항목과 재시도 경로도** 정지 검사 대상이다 |
| 재개 | 파일을 지워도 **정지 전 미발송분·정지 중 예정분·재계산 대상**을 자동 발송하지 않는다. '발송 완료'가 아니라 **'정지로 미발송 종결'** 로 구분해 기록한다 |
| 되돌리기 | 기능을 끄는 상수 변경이 **정지를 우회한 자동 재개가 되어서는 안 된다** |

## 오류 알림 경로 (2026-08-27 결정)

`ALERT_TARGET`으로 고른다. 기본값 **발행 채널**.

| 값 | 언제 | 근거 |
|---|---|---|
| 발행 채널 | 테스트 기간 | 테스트 채널이 곧 상황판. 알림과 콘텐츠를 한곳에서 본다 |
| 개인 DM | 운영 전환 후 | 구독자에게 오류 알림을 보낼 수 없다 |

**알려진 한계 — 같은 경로를 쓰면 같이 죽는다.**
채널로 아예 못 보내는 상황(봇 권한 박탈·채널 삭제·텔레그램 API 차단·채널 레이트리밋)이
바로 알림이 가장 필요한 순간인데, 알림도 그 채널로 가므로 함께 실패한다.
`ALERT_CHAT_ID`(선택)를 채워두면 그 상황에서만 DM으로 우회한다. 비워도 시스템은 돈다.

**구분 규칙:** 오류 알림은 카드(이미지)가 아니라 **텍스트 + `⚠️` 접두 + 인용블록**으로 낸다.
콘텐츠 사이에 섞여도 한눈에 구분되어야 하고, 렌더가 깨진 상황에서도 나갈 수 있어야 하기 때문이다.
발송 상한(`DAILY_MAX`)과 페이서 대상에서 제외한다 — 상한에 걸려 알림이 막히면 안 된다.

## 안전 규칙

1. **자격증명 칸을 만들지 않았다.** 시트는 링크만 있으면 열리는 문서라 비밀을 두는 곳이 아니다.
   봇 토큰·API 키는 GitHub Secrets에 대표님이 직접 넣는다. ✅ **이 규칙은 지금도 유효하다.**
   ⚠️ 다만 **채널 ID(`-100…`)가 시트에 평문으로 들어 있다.** 저장소에서는 같은 값을
   `channel_ref()` 단방향 해시로 감춘다(공개 저장소라서). **기준이 두 곳에서 다르다.**
2. ~~**킬 스위치는 운영 탭 `KILL_SWITCH` 하나다.**~~ ⛔ **철회 — 구현되지 않았다.**
   `KILL_SWITCH`를 읽는 코드는 0곳이다. 급할 때 멈추는 법은 이 문서 위쪽 표를 보라.
3. **`FACT_LOCK`은 끌 수 없다.** 수집 데이터에 없는 사실은 만들지 않는다.
   ✅ **이 규칙은 코드로 살아 있다**(계약·검증에 5곳). 시트 칸과 무관하게 강제된다.
4. ~~**유예(GRACE)·우선순위(PACER)를 시트에서 바꿀 수 있다.**~~ ⛔ **철회 — 바꿔도 반영되지 않는다.**
   값은 `contract.GRACE_SECONDS` / `PACER_PRIORITY`가 갖는다.
   (원래 경고는 여전히 옳다: 유예를 늘리면 "10분 뒤 시작"이 거짓말이 되는 지점이 생긴다.)
5. **`DAILY_MAX`는 편집 정책이 아니라 폭주 방지 안전판**이다.
   ⚠️ **시트의 20은 KBO 한 리그 시절 값이다.** 지금은 `DAILY_MAX_MESSAGES = 500`이고,
   폭주는 별도 상수 `BURST_MAX_MESSAGES = 90`(10분 창)이 잡는다 — v1.14에서 둘을 분리했다.
   이론적 최악 405장(경기별 248 + 리그 60 + 분석 12 + 기타 3 + 라인업 82)이 500의 근거다.
